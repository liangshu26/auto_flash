# XP5 刷机工具

一个图形界面工具，用来从 CI 平台下载刷机包，并给 XPeng XP5 / XCCP / VLMU 板子刷
大包、小包、MCU 固件。界面标题为「XP5 刷机工具 v2.0」。

## 运行环境

- Python 3（带 tkinter，多数桌面版 Python 自带）
- `adb`、`fastboot` 在 PATH 里
- **大包刷机只能在 Linux 上跑**（依赖刷机包内自带的 Linux 版 fastboot）。
  macOS 上可以刷小包和 MCU，大包会被拦下并提示。

## 启动

```bash
python3 flash_gui.py
```

同一时间只能开一个实例，重复启动会提示并退出。

## 界面布局

- 顶部「设备状态」：自动列出当前接到的板子（板型 + 接入方式 adb / fastboot / ssh），
  点「刷新设备」重新探测。
- 中间两个标签页：**下载刷机包** 和 **刷机**。
- 底部「运行日志」：实时输出，按 `[OK]/[WARN]/[ERROR]` 上色；旁边有
  「取消任务」「暂停」「导出日志」「清空日志」。

## 下载刷机包

1. 填「车型」（平台名）。纯直链下载时可不填。
2. 选「下载目录」，可点「浏览」手选，或「自动命名」按车型/日期生成。
3. 在「DT 号配置」里填要下的包，每类可填多个 DT 号（空格分隔）：
   - **VLMU**：大包 DT、小包 DT
   - **XPU**：大包 DT、小包 DT
   - **MCU**：MCUDEBUG
4. 可选「启用轮询」：按设定间隔（分钟）反复检查新包，直到超时（小时）；
   用「取消轮询」或「取消任务」停止。
5. 可选「直接链接」：每行一个完整 http(s) 链接（适用于 RC 等直链，无需 DT 号），
   会和上面的 DT 任务一起下载。
6. 点「开始下载」，确认弹窗后开始。下载支持断点续传与失败自动重试。

## 刷机

1. 选「刷机包目录」（下载目录会自动带过来），点「浏览」或「刷新列表」加载。
2. 在「刷机包列表」里勾选要刷的包。包按类型分组：
   VLMU 大包 / VLMU 小包 / XP5 大包 / XP5 小包 / MCU / VLMU MCU。
   已解压的目录会标 `[已解压]`，可直接刷，无需再解压。
3. 用「XP5 设备」下的 **A 设备 / B 设备** 勾选要刷哪几块 XP5 板。
4. 点「刷选中的包」。工具按包的类型自动选对应脚本：
   - 大包 → `adc_flashall.sh`（自动进 fastboot；进不去时最多重试 3 次）
   - 小包 → `deploy_xpilot_by_adb.sh`（USB 直连优先；无 USB 时走 ssh）
   - MCU → Aurix A/B 双区刷写（adb 优先；无 USB 但 ssh 可达时自动走 ssh）
   - VLMU MCU → OTA 升级（adb 优先；无 USB 但 ssh 可达时自动走 ssh）

刷写顺序固定为 **MCU → 大包 → 小包**（小包必须在大包之后，否则会被大包重写的分区冲掉）；
勾选多个包时工具自动按此排序，确认弹窗也按这个顺序列出。

板型由设备树节点自动识别，不用手动指定。刷写过程不可中途取消（避免刷坏板子），
下载任务可以随时取消。

刷机时日志区下方会显示**进度条**（按「任务 i/N」推进）和**当前阶段**文字
（如「大包 xp5_a · 刷写分区中」「MCU · 刷 A 区」「VLMU MCU · OTA 升级 60%」），
方便知道刷到哪一步；刷机结束后自动隐藏。

## 常见问题

- **设备列表里看不到板子**：先确认 `adb devices` 里状态是 `device`；板子在
  fastboot 模式时要用 `fastboot devices` 看。点「刷新设备」重试。
- **macOS 上大包刷不了**：正常限制，换 Linux 电脑刷大包。
- **更详细的脚本流程与故障排查**：见 `.qoder/skills/xp5-flash/`。
